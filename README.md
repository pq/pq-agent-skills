# 🚧 Agent Skills (WIP)

A collection of custom skills for agentic workflows.

(Limited to Gemini / Antigravity for now.) 

## Skills Included

### 📊 Estimate Conversation Tokens
Analyzes the full conversation transcript logs (`transcript_full.jsonl`) for the **current active conversation** (automatically resolved via environment variables) to estimate character lengths, model invocations (turns), cumulative input/output tokens, and context caching savings.

### 🕵️ Conversation Auditor
Audits previous conversation transcripts to help you identify ways to tune your agentic coding experience. It looks for commonly performed actions, repetitive low-level commands, tool sequences that can be aggregated, and places where the context window is being heavily utilized. It can also extract your raw prompts (`--prompts all`) to perform a Semantic Task Analysis and recommend new workflow-based skills.

### 📉 Analyze Workflow Failures
Fetches recent GitHub Actions workflow runs across multiple repositories, filters out Dependabot runs for separate statistics, and groups failure causes to highlight the top recurring issues. Allows you to easily spot broken tests or systemic infrastructure issues across your GitHub projects.

### 🎛️ Review Tuner (Experimental)
Mines human pull-request review feedback to propose, and optionally verify, changes to a repository's agent guidance (review style guides, bot config, `AGENTS.md`, skills). Three modes: **propose** (drafts changes from review evidence, no replays), **check** (a quick replay: one review per guidance version on a few PRs, verdict *helps / no effect / hurts*), and **evaluate** (thorough replays with a blind judge, fidelity against the real bot, and a confidence rubric). Works on any GitHub repo; favorite repos and reviewer roles live in one config file (`~/.config/review-tuner/config.json`). It only writes to GitHub to open draft PRs in your own fork, and only after you approve each one.

Design background, decisions, lessons, and roadmap: [skills/review-tuner/docs/README.md](skills/review-tuner/docs/README.md).

### 🏷️ Token Categories Explained

The script groups the conversation's raw characters and tool interactions into the following categories:

* **📄 File I/O (Reads/Edits):** Measures the token footprint of reading or writing files in the workspace (via `view_file` or `notebook_edit`).
* **🖥️ Command Execution:** Counts tokens generated by running terminal commands and capturing stdout/stderr (via `run_command`).
* **🔍 Search & Directory Listing:** Tracks tokens spent searching code patterns or listing directory trees (via `grep_search` or `list_dir`).
* **🌐 Web Search & Reads:** Captures tokens consumed during web search lookups or reading documentation links (via `search_web` or `read_url_content`).
* **📚 Knowledge Base Overhead:** Measures the size of automatically injected local Knowledge Items (KIs) at the beginning of the conversation.
* **🧠 Agent Reasoning & Output:** Reflects the model's generated response tokens, including its internal "thinking" process and tool call definitions.
* **💬 User Input & Other Metadata:** Counts raw user prompt text and miscellaneous system-generated messages/metadata.
* **⚙️ System & History Overhead:** Measures the cumulative cost of the core system prompt, agent tool definitions, and previous turn history re-sent on every loop.

### 🧠 Semantic Task Analysis

By analyzing the distinct tasks performed across these conversations, several recurring workflows have emerged:

#### 1. The "Pedantic Reviewer" Workflow
**The Pattern:** You frequently ask the agent to act as a strict reviewer or enforce nits and styleguides.
- *"Please review this build.sh change pedantically. Use our styleguide too"*
- *"Please apply all teh review suggestions"*
- *"Please follow the guidance in our styleguide"*
- *"Ok, I like to use teh dart recommended lints. PLease add those to this project."*

**Recommendation:** Build a **`code-reviewer`** or **`style-enforcer`** skill. Instead of constantly reminding the agent to "be pedantic" or "use the styleguide", you can create a skill that automatically loads your team's style KIs, runs the appropriate linter (`dart analyze`), and applies all fixes automatically when invoked.

#### 2. The "Cross-Repository Porting" Workflow
**The Pattern:** You frequently ask the agent to study a Pull Request in one repository and replicate the architectural changes in another repository.
- *"Create a change for the dart plugin comparable to this: [link]"*
- *"Update the flutter plugin based on the changes in [link]"*

**Recommendation:** Build a **`port-pr`** skill. This skill would instruct the agent on exactly how to fetch a PR via the GitHub MCP, read the diff, map the file structure of the origin repository to the current repository, and apply the conceptual changes methodically. 

#### 3. The "Bug Reproduction & Testing" Workflow
**The Pattern:** You often link to GitHub issues and ask for help reproducing them, followed by unit test assistance.
- *"Look at the bug reported in [link]. Assess and propose a solution."*
- *"How can I reproduce this bug?"*
- *"Hrmpfh. No luck. Could you help with the unit test?"*
- *"I don't like the use of reflection. Could you make the function visible and mark as `@visibleForTesting`?"*

**Recommendation:** Build a **`triage-issue`** skill. When invoked with a GitHub issue link, the agent would automatically fetch the issue body, read the stack trace, search the codebase for the failing lines, and generate a scaffolded unit test designed to reproduce the bug *before* attempting to fix it. It could also codify your preference for `@visibleForTesting` over reflection!

#### 4. The "Documentation Editor" Workflow
**The Pattern:** You frequently iterate on documentation, asking for specific formatting constraints.
- *"Could you update the README to clarify..."*
- *"Could you compress this answer into 2-3 sentences?"*
- *"Could you update the README but maybe with a shortened example?"*

**Recommendation:** Build a **`doc-writer`** skill. This skill could contain your standard rules for brevity, maximum sentence length, and formatting preferences so you don't have to manually prompt the agent to "compress" or "shorten" its output.

### ⚙️ Execution Metrics

#### 1. Tool Usage Frequencies (Top 5)
- `run_command`: 326 uses
- `view_file`: 122 uses
- `replace_file_content`: 105 uses
- `write_to_file`: 67 uses
- `list_dir`: 59 uses

#### 2. The "Global Gap" (Missing System Tools)
**Pattern:** `git status` was executed **37 times** across 3 different conversations and 4 different repositories. `git diff` was run **19 times**.
**Recommendation:** A dedicated **Git MCP Server** would drastically cut down on `run_command` overhead and provide the agent with semantic data rather than raw terminal strings.

#### 3. The "Iterative Struggle" (Tree Crawling)
**Pattern:** The `list_dir` tool was called 3+ consecutive times in a row on 9 different occasions across 5 conversations.
**Recommendation:** A **Semantic Search / Codebase Indexing MCP** (like Bloop or Sourcegraph) could allow the agent to jump straight to the file it needs instead of guessing folder structures.

#### 4. The "Project Boilerplate" (Local Testing Loops)
**Pattern:** `./tool/check_agent_skills.sh` was run 10 times in one repo. `./gradlew test --tests...` was run 7 times. 
**Recommendation:** Create a `.agents/skills/test_workflow.md` file in those specific repositories that tells the agent exactly how to run tests in that codebase so it never has to guess or rediscover the correct build flags.

## 🚀 Installation

### Option 1: Using `npx` (Recommended)
You can use the `skills` npm package to automatically download and link these skills globally:
```bash
# Install all skills in the repository
npx skills add pq/pq-agent-skills

# Or install a specific skill
npx skills add pq/pq-agent-skills --skill conversation-auditor
```

### Option 2: Global Setup (Manual)
Clone the repository and symlink the skills to your global config directory:
```bash
git clone https://github.com/pq/pq-agent-skills.git ~/src/pq-agent-skills
mkdir -p ~/.gemini/config/skills
ln -s ~/src/pq-agent-skills/skills/estimate-conversation-tokens ~/.gemini/config/skills/estimate-conversation-tokens
ln -s ~/src/pq-agent-skills/skills/conversation-auditor ~/.gemini/config/skills/conversation-auditor
ln -s ~/src/pq-agent-skills/skills/analyze-workflow-failures ~/.gemini/config/skills/analyze-workflow-failures
ln -s ~/src/pq-agent-skills/skills/review-tuner ~/.gemini/config/skills/review-tuner
```

### Option 3: Workspace Integration (Project-specific)
Add this repository to your project's `.agents/skills.json` under your `entries` paths:
```json
{
  "entries": [
    { "path": "<path-to-checkout>/pq-agent-skills/skills" }
  ]
}
```
*Note: Make sure to replace `<path-to-checkout>` with the absolute local path to your checkout.*

## 🛠️ Usage / Invocation

Once the skills are installed, you can invoke them in your agent chat interface in two ways:

1. **Via Slash Command:**
   Type the slash command directly in the chat (if applicable):
   ```text
   /estimate-conversation-tokens
   /conversation-auditor
   /analyze-workflow-failures
   /review-tuner
   ```

2. **Via Natural Language:**
   Ask the agent directly:
   > *"Estimate token usage for this conversation."*
   > *"Audit my last conversation and tell me what new skills I should write."*
